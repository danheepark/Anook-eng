## 💡 작업 목적 및 배경 (AN-381)
- **프론트 에스컬레이션 사유(Reasoning) 명확화**: RAG 지식 검색 실패로 인해 고객에게 프론트 연결을 제안하고 수락받았을 때, 직원이 보는 티켓의 '판단 근거'에 "고객 수락"이라는 표면적 이유만 남는 문제를 해결했습니다. 직원이 원인(Root Cause)을 정확히 파악할 수 있도록 프롬프트를 개선했습니다.
- **채팅 배지 버그 수정**: 직원이 고객 채팅방에 진입했음에도 좌측 사이드바의 안 읽은 메시지 배지(레드닷)가 실시간으로 초기화되지 않던 버그를 수정했습니다.
- **지식 관리(RAG) UI 개선**: 프론트데스크 RAG 지식(Knowledge) 검토 탭의 스타일과 표(Table) 컴포넌트를 공통 디자인 시스템에 맞게 일관성 있게 리팩토링했습니다.

## 🛠️ 주요 변경 사항
### 1. AI 라우터 프롬프트 고도화 (`router_prompt.py`)
- `[ESCALATION REASONING RULE]` 추가: `FRONT_ESCALATION` 라우팅 시 고객이 "네"라고 답변한 경우, 과거 대화 맥락을 반드시 참조하여 **실제 에스컬레이션 원인(예: 애견 동반 와인바 정보 부재)**을 `reasoning` 필드에 남기도록 강제했습니다.

### 2. 프론트엔드 채팅 및 컴포넌트 개선 (`frontend/`)
- `requests/page.tsx`: `useEffect` 훅을 추가하여, `activeChatRoom`이 변경되거나 새 메시지를 수신했을 때 현재 활성화된 채팅방의 `newMessageCounts`를 즉시 `0`으로 초기화하도록 수정했습니다.
- `KnowledgeReviewTab.tsx`: 자체 구현되었던 테이블을 프로젝트 표준 공통 컴포넌트(`<Table>`, `<TableHeader>`, `<TableRow>`, `<TableCell>`)로 교체하여 UI 일관성을 확보하고, CSS 모듈을 간소화했습니다.
